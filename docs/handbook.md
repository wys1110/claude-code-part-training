# Claude Code Workshop Handbook

발표 슬라이드에서는 흐름만 다루고, 아래 세부 절차는 이 문서를 참고합니다.

## Git Cheat Sheet

```bash
git status
git diff
git add <file>
git commit -m "Describe the change"
git push
```

원칙:

- `git status`로 현재 상태를 먼저 확인합니다.
- `git diff`로 의도한 변경인지 확인합니다.
- 필요한 파일만 stage합니다.
- 커밋 메시지는 변경 의도를 한 문장으로 씁니다.

## GitHub Pages 배포

1. 저장소의 **Settings**로 이동합니다.
2. **Pages**를 엽니다.
3. 프로젝트의 배포 방식에 맞게 GitHub Actions 또는 브랜치 배포를 선택합니다.
4. Actions가 성공했는지 확인합니다.
5. 저장소의 루트 공개 URL 하나만 사용합니다.

## Pages가 안 될 때

- Actions workflow가 성공했는지 확인합니다.
- 루트에 `index.html`이 생성되는지 확인합니다.
- Pages 설정이 올바른 배포 source를 가리키는지 확인합니다.
- 브라우저 캐시를 우회해 다시 확인합니다.
- 비슷한 별칭 URL을 만들지 말고 루트 URL을 기준으로 문제를 해결합니다.

## 실습 Prompt

```text
이 저장소에 공개 가능한 업무 포트폴리오 웹페이지를 만들어줘.

먼저 질문으로 아래를 확정해줘.
- 대상 사용자
- 페이지 목적
- 공개 가능한 정보
- 필수 섹션
- 완료 기준

그다음 구현 계획을 제시하고, 승인 전에는 파일을 수정하지 마.
승인 후에는 index.html부터 최소 구현하고 브라우저에서 확인해줘.
마지막에는 변경 파일, 검증 결과, 남은 위험을 보고해줘.
```

## 문제 해결 Prompt

```text
현재 문제를 추측하지 말고 증거부터 확인해줘.

1. 재현 조건을 정리한다.
2. 관련 파일과 오류 메시지를 확인한다.
3. 가장 작은 원인 후보를 세운다.
4. 수정 범위를 최소화한다.
5. 수정 후 같은 조건으로 다시 검증한다.
6. 확인한 사실과 추론을 구분해 보고한다.
```

## 공개 전 체크리스트

- 실제 고객명, 사번, 내부 URL이 없는가
- 비공개 수치와 로드맵이 없는가
- 모든 링크가 정상 동작하는가
- 모바일 화면이 깨지지 않는가
- GitHub Pages의 루트 URL이 열리는가
- 저장소와 배포 결과가 동일한가
